# 智造协同平台（ForgeFlow）MVP 规格

## 项目目标

构建一个可本地运行、可现场演示的制造业协同平台，用一条真实业务闭环展示 ERP、OA、MES 在同一个模块化单体中的协作：ERP 建立产品并创建生产订单，OA 审批订单，MES 执行生产并回传报工进度，平台仪表盘展示最终状态。

这是作品集 MVP，不宣称实现完整 ERP/MES/OA。优先做到“端到端可运行、业务规则可测试、演示数据可复现”，再扩展采购、库存、质量等能力。

## 核心演示流程

1. 计划员维护成品和原料，并为成品配置 BOM。
2. 计划员创建生产订单，订单初始状态为 `DRAFT`，并提交审批后进入 `PENDING_APPROVAL`。
3. 审批员在 OA 待办中批准或驳回订单；每次提交和审批动作写入可追溯记录。驳回为终态，不支持本 MVP 内重新提交。
4. 获批订单进入 MES 工作台；操作员启动生产并分批报工，每批包含合格数和不合格数。
5. 已报工总数（合格数 + 不合格数）不得超过计划数量；累计总数达到计划量时订单变为 `COMPLETED`。报工过程同时维护合格数、不合格数和累计进度。
6. 仪表盘汇总订单数量、待审批数量、生产中数量、完工数量及合格/不合格报工数。

## 用户与权限

- `ADMIN`：所有 MVP 操作。
- `PLANNER`：维护产品/BOM，创建并提交生产订单。
- `APPROVER`：审批或驳回待审批订单。
- `OPERATOR`：启动已批准订单并提交报工。

使用真实服务端认证和 API 权限控制；本地开发环境提供仅用于演示的种子账号，README 明确标注默认口令只适用于本地演示，生产部署必须替换凭据与密钥。

## 功能范围

### ERP

- 产品/物料主数据：编码唯一，名称、类型（成品/原料）、计量单位、启用状态。
- BOM：成品关联一个或多个原料及正数用量；MVP 不做库存扣减或 MRP 运算。
- 生产订单：选择成品和正整数计划量，生成唯一订单号并维护状态。

### OA

- 针对生产订单的一步审批：提交、批准、驳回。
- 状态不允许跳跃或重复处理；拒绝非 `PENDING_APPROVAL` 订单的决策。
- 记录动作人、动作、意见和时间。

### MES

- 查询已批准/生产中订单，启动订单并进行分批报工。
- 每笔报工至少包含一个正数的合格数或不合格数；累计报工数不能超过计划量。
- 报工写入明细，并在同一事务内更新累计值、进度和订单状态。

### 平台与前端

- 基于角色的登录与接口鉴权。
- Vue 3 单页应用：登录、仪表盘、产品/BOM、生产订单、OA 审批、MES 报工工作台。
- 提供可重复的本地演示数据与启动说明。

## 非目标（首版不做）

财务、采购、销售全链路、库存台账/领料与退料、复杂多级流程设计器、工资/人事、APS/MRP、高级质量管理、设备 IoT、消息队列、微服务、分布式事务、多租户和 Redis 缓存。后续按面试反馈或项目时间再选一项扩展。

## 建议技术与架构

- 后端：Java 17 目标版本、Spring Boot 3.x、Spring Security、MyBatis-Plus、Flyway、Maven Wrapper。
- 数据：MySQL 8；单库单 schema。Flyway 管理迁移；数据库连接与密钥通过环境变量配置。
- 前端：Vue 3、Vite、Element Plus；开发代理转发 `/api`。
- 本地运行：Docker Compose 提供 MySQL；不引入 Redis 或消息中间件。
- 架构：一个 Spring Boot 可执行应用、一个数据库，按 `auth`、`erp`、`oa`、`mes`、`dashboard` 特性包组织；跨模块通过应用服务调用，不做网络化服务拆分。涉及订单状态、审批记录和报工明细的写操作使用事务。

## 验收标准

- 按 README 能完成配置、启动后端和前端，演示用户可登录。
- 可从产品/BOM维护开始，走通创建订单、审批、MES 启动、分批报工、仪表盘更新的完整流程。
- 未批准订单不能进入生产；错误角色不能执行审批或报工；重复审批、零/负数报工、超计划报工均被拒绝。
- 核心状态转换与业务约束有自动化测试；项目构建与测试命令在 README 中明确。
- README 区分已实现功能与后续规划；简历表述只覆盖代码中确实可演示的功能。

## 环境备注

当前工作区已有 JDK 21、Node.js/npm、Git 和 MySQL 客户端，但没有 Maven、Docker 或本地 MySQL 服务。因此项目将包含 Maven Wrapper 与 Docker Compose 配置；当前环境可用 Wrapper 运行不依赖数据库的测试与前端构建。MySQL 联调/容器验收需在可用的 Docker/MySQL 环境完成，不能在本环境中假称已验证。
