# ForgeFlow 岗位工作台与演示数据增强规格

## 目标

在现有 ForgeFlow 制造闭环上增加清晰的岗位分工、岗位待办入口和能展示流程状态的演示数据，让不同岗位登录后能看到自己要处理的业务，并进入现有页面用表格和操作按钮完成业务动作。保持项目适合作品集演示的中等复杂度，不扩成完整 ERP。

## 岗位与职责

- `ADMIN` 系统管理员：查看全部模块与工作台待办。
- `PLANNER` 计划员：维护产品/BOM、创建并提交生产订单。
- `APPROVER` 审批员：审批或驳回生产订单。
- `WAREHOUSE` 仓库员：登记原料收货、核对库存、为已批准订单备料和领料。
- `PURCHASER` 采购员：只针对生产订单的物料短缺生成补料采购单并登记到货。
- `OPERATOR` 生产操作员：启动已领料订单并分批报工。
- `QUALITY_INSPECTOR` 质检员：检验 MES 合格报工，并将通过数量转入成品库存。

服务端 API 权限是最终权限边界；前端菜单和路由按同一岗位职责展示。现有 `APPROVER` 不再兼任质量检验，质量职责由独立的 `QUALITY_INSPECTOR` 演示账号承担。

## 岗位工作台与表格

- 仪表盘继续展示后端实时生产汇总，并新增“我的待办”区，按登录岗位调用其有权访问的现有业务 API，展示真实待处理记录和数量。
- 待办行可跳转到对应业务模块；处理仍复用现有业务表格和行操作，不新增通用表格编辑器，也不绕过现有业务规则。
- 各岗位只能看到与其职责相符的导航与工作台队列；管理员可以查看各岗位待办。
- 新建/审批/备料/领料/采购收货/报工/质检/成品入库仍调用现有业务 API，保留事务、状态迁移与权限校验。

## 演示数据

- 演示产品目录扩为 4 种成品、6 种原料，并给每种成品配置多项 BOM。
- 增加覆盖生产订单六种状态（草稿、待审批、已批准、已驳回、生产中、已完工）的关联业务数据；订单、审批记录、物料需求、库存流水、采购单、报工、质检和成品入库的引用与数量必须一致。
- 演示数据应覆盖仓库待备/待领料、短缺补料采购待到货、MES 执行、待质检和已检验入库等岗位队列。
- 采购仍只能按已批准生产订单的 BOM 物料短缺量补料；不加入供应商管理、采购审批或与生产无关的采购。
- 新增数据放入仅 `dev` profile 加载的 Flyway 演示迁移；演示用户密码继续使用现有 `DEMO_PASSWORD_HASH` 占位符，不写入明文密码。

## 非目标

不增加财务、销售、HR、供应商主数据、复杂多级审批、MRP/APS、通用电子表格引擎、微服务、缓存、消息队列或其他新基础设施；不改动现有制造闭环核心状态与数量规则。

## 验收标准

1. 七种岗位分别登录时，只看到对应菜单；未经授权的服务端 API 请求仍被拒绝。
2. 仪表盘待办来自真实 API 数据，能分别呈现计划、审批、仓库、采购、生产、质检任务，并能进入相应业务处理页。
3. 产品/原料/BOM 和生产订单台账有足够的演示记录，多个岗位队列在本地开发环境下有可见内容。
4. 种子订单状态和关联明细符合业务不变量；补料采购只覆盖缺料量，采购到货、报工、质检及成品入库数量相互吻合。
5. 既有业务服务、接口、状态转换和制造闭环自动化测试不回归；更新 README 中岗位账号说明与演示路径。
6. 运行 Maven 后端测试/打包与 npm 前端测试/生产构建；未实际执行的 MySQL 集成验证必须明确披露。
